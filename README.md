# AI 海外达人营销助手（Influencer Marketing Copilot）

帮助海外营销人员从一批候选达人中，筛选出值得进一步人工评估的对象，解释匹配原因、展示证据与风险，并辅助制定优先联系名单。

**当前版本：Phase 2（规则链路 + AI 语义分析；AI 需要配置 API Key，未配置时规则链路照常可用）。**
本文档只描述已经实现并验证过的内容；未实现的部分会在「还没做什么」里明确列出。

---

## 1. 这个项目解决什么问题

达人初筛通常靠人工翻账号：看内容、看粉丝、看互动、判断和产品搭不搭。人一多就变成体力活，而且判断标准藏在每个人的脑子里，事后说不清为什么选他。

这个工具把这件事拆成两段：

1. **确定性规则**：能算的（粉丝量门槛、市场/语言匹配、互动率、关键词与类目重合）交给程序，结果可复现、可逐条解释。
2. **AI 语义判断**（Phase 2）：产品卖点和达人内容是否真的契合、有没有风险，交给大模型，但必须给出证据字段、缺失信息和人工核查建议。

项目刻意不做的事：不做「输入产品、自动生成一份完整投放方案」这种演示型产品，也不预测销售额或 ROI。

## 2. 谁在用

海外营销 / 达人营销执行同学（TikTok、Instagram 等平台），尤其是需要在一两百个候选达人中选出 10-20 个优先联系对象、并且要向主管说明「为什么是这几个人」的场景。

## 3. 典型使用流程

配置营销任务 → 加载或上传达人数据 → 规则初筛 → 查看推荐依据与风险 → 人工确认 → 导出结果

## 4. 为什么不能只靠人工、也不能只靠大模型

- 只靠人工：筛选标准不可复现、不可解释，换个人结果就不同。
- 只靠大模型：基础算术（互动率、粉丝门槛）不需要也不应该交给模型；模型还容易在证据不足时给出确定结论。
- 所以：**规则负责可验证的部分，AI 负责语义部分，人工保留最终决定权**。人工的修改不会覆盖规则或 AI 的原始输出。

## 6. DeepSeek API 配置

```powershell
Copy-Item .env.example .env
notepad .env     # 填入你自己的 DEEPSEEK_API_KEY
```

- API Key 只从本机 `.env` 读取，`.env` 已在 `.gitignore` 中，不会进 Git。
- **不配置 API 也能完整跑通规则链路**，界面会明确显示 AI 环节未配置，不会用假结果顶替。
- 配置后，第 ④ 步「AI 语义分析」会在**调用前**显示候选数、命中缓存数、预计实际调用次数与模型版本，并需要你再点一次确认，避免意外消耗额度。
- AI 结论必须带证据字段引用；证据若在原始数据里找不到、或出现输入中没有的数字，会被单独标出来。

| 数据类型 | 位置 | 性质 |

## 8. 规则说明（重要：权重是项目初始假设）

| 维度 | 默认权重 | 说明 |
|---|---|---|
| 内容相关性 | 30% | 关键词与类目重合（**确定性匹配，不是语义判断**） |
| 目标市场匹配 | 20% | `market` 与目标市场比对（含常见别名） |
| 互动表现 | 20% | 优先用数据自带互动率，缺失时依次降级并标注口径 |
| 受众匹配 | 15% | 目标受众关键词与 `audience_description` 重合 |
| 合作可行性 | 15% | 平台与语言匹配（合作经历仅作定性提示） |

三条硬规则：

1. **硬性条件只来自你在表单里填写的要求**（最低粉丝量、内容语言、目标地区），系统不内置任何阈值。
2. **缺失不等于不合格**：数据缺失记「无法判定」，进入「需人工核实」分组，不自动淘汰，排序排在有明确结论者之后。
3. **权重是项目初始假设，不是行业标准**，可在界面调整；调整会改变 `rule_config_hash`，旧结果随即标记为「已过期」。

总分按实际参与的维度加权归一化：`Σ(维度分 × 权重) / Σ(参与维度权重)`，因此不会因为缺数据而被判低分；同时输出「信息完整度」供参考。

互动率口径优先级：

1. 数据自带的 `engagement_rate`（口径由数据提供方说明）
2. `(likes + comments) / follower_count`（项目内近似口径）
3. `average_views / follower_count`（降级口径，只作播放表现参考，**不等同互动率**）
4. 三者都不可用 → 信息不足，不参与打分

## 9. 结果追溯

每次运行生成 `runtime/runs/<run_id>/`：

| 文件 | 内容 |
|---|---|
| `meta.json` | run_id、分析时间、数据来源、data_hash、数据条数、任务配置与 hash、rule_version、rule_config_hash、prompt_version、模型标识、分析条数、app_version |
| `rule_results.csv` | 规则结果明细 |
| `ai_results.json` | AI 逐条结论、错误分类与证据核对结果（未运行 AI 时不产生该文件） |
| `decisions.json` | 人工审核状态与备注（与规则/AI 结果分开存储） |

导出为**两个文件**：结果 CSV（UTF-8 BOM，Excel 打开不乱码）+ 元数据 JSON（数据来源、分析时间、版本信息）。失败或信息不足的记录全部保留并标注状态，不静默删除。

## 11. 还没做什么（诚实清单）

- **AI 已接入但未联调真实 API**：全部失败分支用假客户端测过，真实返回的格式稳定性需要一次真实调用确认。
- **结果过期提示（Phase 3）尚未完善**：目前规则层已有 data_hash / task_hash / rule_config_hash 的比对与提示，AI 结果的过期联动仍在 Phase 3。
- **离线评估（Phase 4）未开始**：`data/evaluation/` 目前为空。
- **界面未做视觉打磨**：功能完整优先，没有图表、没有英文界面（文案已集中便于后续 i18n）。
- **没有实现**：登录/权限、数据库、真实平台抓取、自动联系达人、ROI 预测、多 Agent、向量检索。
- 规则中的内容相关性只是词面/类目匹配，**不代表语义判断**，这是设计上的分工，不是缺陷。
