# Phase 2 实施报告：接入 DeepSeek

日期：2026-10-14
范围：AI 语义分析（Prompt 设计、客户端、结构化输出校验、证据核对、缓存、单条重试、界面与导出）

## 1. 本阶段完成了什么

- `prompts/creator_analysis_v1.md`：结构化输出 Prompt，固定了字段名、枚举与硬性规则（不得编造数字、证据必须逐字来自输入、信息不足必须承认）。
- `src/ai_client.py`：DeepSeek（OpenAI 兼容接口）客户端。Key 只从环境变量 / `.env` 读取；错误分成 timeout / auth / rate_limit / network / server / request / format / unknown 八类；重试上限 2 次且只对可恢复错误重试；日志与异常信息做 Key 脱敏。
- `src/ai_analyzer.py`：组装 payload（**刻意不传规则加权总分**，避免锚定）、Pydantic 校验、证据逐条核对、编造数字启发式检测、本地缓存去重、单条重试、调用量预估。
- `src/models.py`：新增 `Evidence` / `VerdictItem` / `RiskItem` / `AIAnalysis` / `AIAnalysisRecord`，让 Prompt、校验、界面、导出共用一套契约。
- `app.py` 新增第 ④ 步「AI 语义分析」：未配置 Key 时明确显示不可用且不提供假入口；配置后显示预计调用次数并要求二次确认；逐条展示判断、理由、证据、风险；失败条目可单独重试。
- 导出扩展：结果 CSV 增加 AI 状态、三个维度的判断、推荐理由、风险、缺失信息、人工核查建议、证据问题、可疑数字，并标注数据来源与模型版本。

## 2. 关键设计决策

| 决策 | 原因 |
|---|---|
| 结构上把 AI 与规则彻底分开 | 粉丝门槛、互动率这类算术不该交给模型；语义判断才交给模型 |
| payload 不含规则总分 | 避免模型被分数锚定，变成「复述规则」而不是独立判断 |
| 证据必须能在原字段里逐字找到 | 这是防幻觉最有效的一道闸门：模型引用不存在的原文会被立刻标出 |
| 证据问题只标记、不删除结论 | 直接丢弃会掩盖问题；标出来并降低可信度，由人来判断 |
| 编造数字做启发式检测 | 长数字若无法在输入中找到即标记；会有误报，所以只提示不断言 |
| 缓存只做优化 | 缓存写不进去（权限、磁盘）时降级为「本次不缓存」，不影响分析（有测试覆盖） |
| 单条失败不伪造 | 失败一律记 `failed` + 分类原因，界面与导出都如实展示 |

## 3. 你现在能用什么

没有 Key：第 ④ 步显示「未配置 DEEPSEEK_API_KEY」，规则 → 人工审核 → 导出照常可用。

有 Key（把 `.env.example` 复制成 `.env` 并填入）：

1. 第 ④ 步选择「分析排名前 N 名」（默认 10，上限 30）。
2. 界面显示候选数 / 命中缓存数 / 预计实际调用次数 / 模型 / Prompt 版本。
3. 勾选确认后才会真正发起调用（费用闸门）。
4. 结果按条展示：判断、理由、证据字段与原文、风险、缺失信息、人工核查建议。
5. 失败或信息不足的条目单独重试，不影响其他条目。

## 5. 已知限制与风险

1. 真实 API 未联调：`openai` 3.30.0 的接口契约已在本机离线核对（`chat.completions.create` 支持 `model`/`messages`/`response_format`/`temperature`/`timeout`，异常类齐全），但 DeepSeek 实际返回是否稳定符合 schema，需要一次真实调用确认。
2. 编造数字检测是启发式的，可能出现误报（例如模型把 45200 写成「约 4.5 万」）。界面上标记为「可疑」而不是「错误」。
3. 证据核对是逐字匹配：模型若把原文稍作改写（哪怕语义一致）也会被标记。这是刻意从严，宁可多标。
4. 成本：单条一次的 token 量取决于达人记录长度；界面在调用前给出次数预估，但**不预估金额**（价格会变，写了反而误导）。
5. 失败重试是手动的（界面上按条重试），没有做自动批量重试，避免意外放大费用。

## 7. 环境问题记录：pytest 临时目录权限（已修复）

**现象**：在我这边跑测试全绿，但换到你的账户下执行 `pytest` 会报 `PermissionError: [WinError 5] … pytest-of-liang`，12 个用到临时目录的测试全部失败。

**原因**：我的部分命令是跑在一个隔离沙箱里的，身份是 `codexsandboxoffline`（不是你），它创建的 `%TEMP%\pytest-of-liang` 目录你无权访问；pytest 启动时扫描该目录即报错。

**处理**：

- 已从沙箱侧删除该目录；
- 之后所有测试都用你的账户执行，临时目录归属正确；
- 复核结果：以 `liang` 身份执行 `python -m pytest -q` → `70 passed`，临时目录正常重建。

**给你的提醒**：如果你在自己的终端里看到类似的 `PermissionError`，先删除 `%TEMP%\pytest-of-liang` 再重跑即可。
